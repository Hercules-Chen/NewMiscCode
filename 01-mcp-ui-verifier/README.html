mcp-ui-verifier：用真實瀏覽器驗證網頁 UI 的 MCP 伺服器

Playwright + Model Context Protocol（stdio）· 紅框標註截圖 · 自帶 HTML 報告 · 繁體中文 / English

概覽 安裝 逐步驗證指南 註冊到 Claude Code MCP 工具 情境 JSON CLI 與選項 除錯與日誌 Windows 啟動器 限制與疑難排解 開發者指南 English

概覽

這個工具讓 AI 代理（例如 Claude Code）透過 MCP 協定操作一個真實的 Chromium 瀏覽器，執行點擊、輸入、斷言等動作來驗證網頁 UI，並自動留下證據：

  • 紅框標註截圖：把有問題的元素用紅色方框加編號標籤框起來；找不到的元素、主控台錯誤會列在右上角的紅色橫幅中。
  • 自帶 HTML 報告（單一檔案，截圖以 base64 內嵌）：分頁顯示「摘要 / 步驟 / 截圖 / 主控台訊息 / 環境與計時」，支援錨點連結（例如 report.html#step-9）。
  • 主控台錯誤收集：console.error、未捕捉例外（pageerror）、失敗的請求、HTTP 4xx/5xx 回應。
  • 結構化日誌（JSONL，含等級）以及可選的 Playwright trace.zip。
  • 同一套引擎也提供純 CLI（node src/cli.js run scenario.json），不需要 MCP 也能讓人直接使用。

安裝

需求

  • Node.js 20 以上（開發與測試使用 Node 22）。
  • Playwright 用的 Chromium（第一次安裝時下載，約 150 MB）。

Windows（繁體中文環境）

  1. 把整個 01-mcp-ui-verifier 資料夾放到本機，例如 C:\Tools\newmisccode\01-mcp-ui-verifier。
  2. 雙擊 setup.bat。它會執行 npm install 與 npx playwright install chromium，最後顯示結束代碼（0 表示成功）。

或在 PowerShell / 命令提示字元手動執行：

cd C:\Tools\newmisccode\01-mcp-ui-verifier
npm install
npx playwright install chromium

Linux / macOS

cd 01-mcp-ui-verifier
npm install
npx playwright install chromium   # 若系統已預先安裝瀏覽器可略過

關於瀏覽器位置：本專案把 playwright@1.63.0 列為本地相依套件，並使用 Playwright 的預設瀏覽器位置（Windows 為 %LOCALAPPDATA%\ms-playwright，Linux 為 ~/.cache/ms-playwright，或環境變數 PLAYWRIGHT_BROWSERS_PATH 指定的位置）。 本專案的開發環境（Linux 容器）已預先設定 PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers，因此沒有執行 playwright install。

如果不想下載瀏覽器，也可以用 --browser-path（或環境變數 UIV_BROWSER_PATH）指向已安裝的 Chrome，例如 --browser-path "C:\Program Files\Google\Chrome\Application\chrome.exe"。

逐步驗證指南（給同事重現用）

  1. 安裝相依套件：npm install，接著 npx playwright install chromium（Windows 可直接雙擊 setup.bat）。

  2. 執行自動測試：npm test（或 run-tests.bat）。

    • test/mcp.test.js：用 MCP SDK 的 Client + StdioClientTransport 啟動 src/server.js，列出工具並實際呼叫 open_page / fill / click / assert_text / check_console_errors / screenshot_annotate / generate_report / run_scenario。
    • test/cli.test.js：執行 CLI 示範，用 Chromium 開啟產生的報告，逐一點選分頁並檢查內容與內嵌圖片。

  3. 執行 CLI 示範：node src/cli.js demo（或雙擊 run-demo.bat）。
    它會在隨機埠啟動示範網站，執行 scenarios/demo.json，預期輸出類似：

註冊到 Claude Code

方法一：claude mcp add

Windows（請改成實際路徑）：

claude mcp add ui-verifier -- node C:\Tools\newmisccode\01-mcp-ui-verifier\src\server.js --lang zh-TW

Linux / macOS：

claude mcp add ui-verifier -- node /path/to/01-mcp-ui-verifier/src/server.js --lang zh-TW

加上 --scope user 可讓所有專案都能使用；加上 -e UIV_HEADED=1 之類可傳環境變數。-- 之後的參數會原封不動傳給伺服器（可用的伺服器參數與 CLI 相同，例如 --headed、--trace、--base-url、--out）。

方法二：JSON 設定（專案根目錄的 .mcp.json）

{
  "mcpServers": {
    "ui-verifier": {
      "type": "stdio",
      "command": "node",
      "args": [
        "C:\\Tools\\newmisccode\\01-mcp-ui-verifier\\src\\server.js",
        "--lang", "zh-TW",
        "--base-url", "http://127.0.0.1:4173/"
      ],
      "env": {
        "UIV_TRACE": "1"
      }
    }
  }
}

也可以用一行指令加入同樣的設定（命令提示字元；路徑用正斜線 / 可避免跳脫問題，Node.js 在 Windows 上可正常解析）：

claude mcp add-json ui-verifier "{\"type\":\"stdio\",\"command\":\"node\",\"args\":[\"C:/Tools/newmisccode/01-mcp-ui-verifier/src/server.js\",\"--lang\",\"zh-TW\"]}"

確認連線

  1. claude mcp list 應列出 ui-verifier。
  2. 在 Claude Code 中輸入 /mcp，狀態應為 connected，並可看到 14 個工具。

範例提示詞

請用 ui-verifier 驗證 http://127.0.0.1:4173/：
1. 開啟頁面，在 #username 輸入「小明」並點擊 #login-btn，確認 #login-msg 包含「歡迎，小明」。
2. 確認 #price 顯示「NT$ 1,280」。
3. 點擊 #add-to-cart 後檢查主控台錯誤。
4. 把所有有問題的元素用紅框截圖標註，最後產生報告並告訴我報告路徑。
如果在 MCP 模式下出現「Executable doesn't exist」（找不到瀏覽器），代表伺服器行程拿不到瀏覽器路徑：請先執行 npx playwright install chromium，或在設定的 env 中加入 "PLAYWRIGHT_BROWSERS_PATH"，或用 --browser-path 指定 Chrome。

其他 MCP 用戶端

任何支援 stdio 的 MCP 用戶端都可使用：命令為 node，參數為 src/server.js 的完整路徑。test/mcp.test.js 就是一個最小的 SDK 用戶端範例。

MCP 工具一覽

瀏覽器在第一次呼叫時才啟動；同一個工作階段的所有步驟都會被記錄，供 generate_report 使用。斷言失敗時工具結果以「失敗 / FAIL」開頭，並附上紅框截圖（image/png）。選擇器支援 Playwright 語法（CSS、text=登入、role=button[name="登入"] 等）。

工具參數說明
open_pageurl, waitUntil?開啟網址（相對路徑會以 --base-url 解析），回傳 HTTP 狀態、標題、載入計時。
clickselector, timeout?點擊第一個符合的元素。
fillselector, text, secret?輸入文字；secret: true 會在報告與日誌中遮蔽內容。
pressselector, key按鍵，例如 Enter、Control+A。
assert_visibleselector, timeout?確認元素在逾時內出現且可見。
assert_hiddenselector, timeout?確認元素不可見或不存在。
assert_textselector, expected, mode?比對可見文字；mode 為 contains（預設）、equals、regex，空白會正規化。
check_console_errorsexpectNone?, all?, ignore?檢查自上次檢查以來的主控台錯誤、未捕捉例外、請求失敗、HTTP ≥ 400。失敗截圖會框出「最後互動的元素」。
screenshot_annotateselectors[], label?, labels?, fullPage?在元素周圍畫紅框與編號標籤後截圖（預設整頁），找不到的元素列在紅色橫幅。回傳 PNG。
waitms等待指定毫秒。
get_page_infomaxChars?回傳目前網址、標題、可見文字前 N 字，協助代理決定要驗證的選擇器。
generate_report—為目前工作階段產生 HTML 報告，回傳路徑與摘要。
close_browser—產生報告、儲存 trace.zip（若啟用）、關閉瀏覽器；下次呼叫會開新的執行資料夾。
run_scenariofile?, scenario?, baseUrl?以全新瀏覽器執行情境 JSON（檔案路徑或內嵌物件），並產生報告。

情境 JSON 格式

{
  "name": "demo-shop",
  "baseUrl": "http://127.0.0.1:4173/",
  "stopOnFailure": false,
  "timeout": 5000,
  "viewport": { "width": 1280, "height": 800 },
  "steps": [
    { "action": "open", "url": "/" },
    { "action": "fill", "selector": "#username", "text": "小明" },
    { "action": "fill", "selector": "#password", "text": "secret123", "secret": true },
    { "action": "click", "selector": "#login-btn" },
    { "action": "assert_text", "selector": "#login-msg", "expected": "歡迎，小明" },
    { "action": "assert_text", "selector": "#price", "expected": "NT$ 1,280", "timeout": 1500 },
    { "action": "click", "selector": "#add-to-cart" },
    { "action": "check_console_errors", "ignore": ["favicon"] },
    { "action": "assert_visible", "selector": "footer #contact-link" },
    { "action": "screenshot_annotate", "selectors": ["#price", "#add-to-cart"],
      "labels": ["價格錯誤", "會丟出錯誤"], "label": "問題元素總覽" }
  ]
}
欄位說明
name情境名稱（用於執行資料夾名稱與報告標題），省略時使用檔名。
baseUrl相對網址的基底；可被 CLI --base-url 覆寫。
stopOnFailuretrue 時第一個失敗後其餘步驟標為「略過」。預設 false，盡量收集證據。
timeout / viewport情境層級的逾時與視窗大小（CLI --timeout 優先）。
步驟共用欄位action（必填）、timeout、screenshotOnFail（預設 true）。
動作open、click（waitAfter）、fill、press、wait（ms）、wait_for、assert_visible、assert_hidden、assert_text（mode/exact）、check_console_errors（expectNone、all、ignore、settleMs）、screenshot_annotate（selectors、labels、label、fullPage、failOnMissing）。

情境檔可為 UTF-8（有無 BOM 皆可，以相容 Windows 記事本）。

除錯與日誌

JSONL 結構化日誌

每一行都是一個 JSON 物件，包含 ts（ISO 時間）、level、msg 與相關欄位，例如：

{"ts":"2026-11-05T04:07:19.731Z","level":"warn","msg":"step.end","session":"demo-shop","no":9,"action":"assert_text","status":"fail","durationMs":1570,"message":"#price 的文字不符..."}

常見事件：browser.launch、step.start、step.end、page.console、screenshot、trace.saved、report.written、tool.call、tool.result。在 PowerShell 可用以下方式篩選：

Get-Content .\log.jsonl -Encoding UTF8 | ConvertFrom-Json | Where-Object level -eq 'warn' | Format-Table ts,msg,action,message
MCP 伺服器的 stdout 是通訊通道，所以伺服器絕不寫入 stdout；診斷訊息只寫到 JSONL 檔，--debug 時另外輸出到 stderr。

Playwright Trace

node src/cli.js demo --trace
npx playwright show-trace "<執行資料夾>\trace.zip"

Trace 檢視器可逐步查看每個動作前後的 DOM 快照、網路請求與主控台訊息。

Chrome DevTools

  • --devtools：開啟有畫面的瀏覽器並自動打開 DevTools。
  • --debug：有畫面 + 放慢動作 + debug 日誌 + trace，適合觀察腳本實際在做什麼。
  • --cdp-port 9222：可在另一個 Chrome 開啟 chrome://inspect，按「Configure…」加入 localhost:9222 後檢查（無畫面模式也可用）。
  • MCP 模式下同樣適用：把選項加在 claude mcp add ... -- node src/server.js --devtools。

Windows 啟動器

模式為 .bat → uiv.ps1 → node。.bat 檔為純 ASCII，會切換到自己所在的資料夾（pushd "%~dp0"）、顯示目前路徑、執行後顯示結束代碼並 pause。uiv.ps1 為含 BOM 的 UTF-8（Windows PowerShell 5.1 需要 BOM 才能正確讀中文），並把主控台編碼設為 UTF-8。

檔案動作

run-demo.bat [選項]執行示範（例如 run-demo.bat --lang en --devtools）
run-scenario.bat <scenario.json> [選項]執行指定情境；相對路徑以專案資料夾為準
serve-demo.bat只啟動示範網站於 http://127.0.0.1:4173/
run-tests.batnode --test（等同 npm test）

報告預設寫到 C:\ProgramData\NewMiscCode\01-mcp-ui-verifier\run-…\report.html。若該位置沒有寫入權限，請加 --out 指定其他資料夾，例如 run-demo.bat --out "%USERPROFILE%\Documents\ui-verifier"。

限制與疑難排解

已知限制

  • 只支援 Chromium（未測試 Firefox / WebKit）。
  • 每個 MCP 伺服器同時只有一個頁面（不支援多分頁 / 多視窗、iframe 內元素的紅框位置以主框架座標計算，可能不準）。
  • 紅框以注入覆蓋層 div 的方式繪製，截圖後立即移除；若網頁有極高 z-index 或 Shadow DOM 特殊排版，框線位置可能有偏差。
  • 報告把截圖以 base64 內嵌，截圖很多時檔案會變大（每張約 50–100 KB）。
  • Windows 啟動器（.bat / .ps1）在 Linux 開發環境中無法實際執行，只做了編碼與內容檢查；請在 Windows 上先以 run-demo.bat 試跑一次。

疑難排解

症狀處理方式
Executable doesn't exist at ...ms-playwright...執行 npx playwright install chromium，或用 --browser-path 指定 Chrome。MCP 模式下可在設定的 env 加入 PLAYWRIGHT_BROWSERS_PATH。
寫入 C:\ProgramData\... 失敗（EPERM）用 --out 或 UIV_OUTPUT_DIR 改到有權限的資料夾。
PowerShell 顯示「無法載入，因為這個系統上已停用指令碼執行」請透過 .bat 啟動（已帶 -ExecutionPolicy Bypass）。
主控台中文變成亂碼uiv.ps1 已設定 UTF-8；直接使用 cmd 時可先執行 chcp 65001。

如何新增一個驗證動作（例：assert_attribute）

  1. src/scenario.js：把 'assert_attribute' 加入 ACTIONS。
  2. src/session.js 的 _dispatch()：新增 case 'assert_attribute':，回傳 { ok, message, data? }；失敗時 runStep() 會自動以 step.selector 畫紅框截圖。
  3. src/i18n.js：zh-TW 與 en 都加上訊息字串，用 t(L, 'key', { 變數 }) 取用。
  4. src/server.js：reg('assert_attribute', { title, description, inputSchema: { selector: z.string(), name: z.string(), expected: z.string(), timeout: timeoutArg } }, stepTool('assert_attribute', (a) => a));
  5. test/mcp.test.js 加一個呼叫案例；npm test 必須全過。
  6. 更新本文件「MCP 工具」與「情境 JSON」分頁，最後執行 npm run audit-text。

對外介面約定（請保持相容）

  • 工具名稱與參數名稱一旦發佈就不要改名；要改請新增工具並保留舊的。
  • 工具結果第一行以「通過 / 失敗」（en：PASS / FAIL）開頭，後接 JSON；AI 代理依此判斷，格式請保持。
  • CLI 結束代碼：0 全過、1 有失敗、2 用法錯誤或例外。批次檔與 CI 依此判斷。
  • 輸出資料夾結構：run-<時間>-<名稱>/report.html、log.jsonl、screenshots/、trace.zip。

English summary

mcp-ui-verifier is an MCP server (Node.js ESM, @modelcontextprotocol/sdk, stdio) that lets an AI agent drive a real Chromium through Playwright to verify web UIs. It produces evidence: full-page screenshots with red boxes and numbered labels around problem elements (missing elements and console errors are listed in a red banner), and a self-contained, tabbed HTML report (summary / steps / screenshots / console / environment and timings) in zh-TW or English.

Quick start

npm install
npx playwright install chromium     # skip if browsers are already provisioned
npm test                            # MCP stdio client test + CLI test + text audit
node src/cli.js demo --lang en      # runs the demo site with 3 deliberate bugs -> 10 passed / 4 failed
node src/cli.js run scenarios/demo-pass.json --base-url http://127.0.0.1:4173/   # needs: node src/cli.js serve-demo

Register with Claude Code

claude mcp add ui-verifier -- node /abs/path/01-mcp-ui-verifier/src/server.js --lang en

Tools: open_page, click, fill, press, assert_visible, assert_hidden, assert_text, check_console_errors, screenshot_annotate, wait, get_page_info, generate_report, close_browser, run_scenario.

Debugging: --debug (headed, slowMo, debug log, trace), --devtools, --cdp-port 9222, --trace. Logs are JSONL; output defaults to %ProgramData%\NewMiscCode\01-mcp-ui-verifier on Windows and ./output elsewhere (--out / UIV_OUTPUT_DIR to override). Exit codes: 0 pass, 1 failures, 2 error.
